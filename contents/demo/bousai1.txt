# 制作依頼：AAA志向の防災用リアルタイム津波浸水シミュレーター（沿岸住宅街・人物なし）

これは、アイデア提案、制作計画、サンプル画像だけを求める依頼ではありません。

Three.js / WebGL を用いて、海に近い一般的な住宅街に津波が流れ込み、

街が浸水し、水が引いたあとも湛水と痕跡が残る様子を、

実際に動かせるリアルタイムシミュレーターとして制作してください。

想定用途は、**自治体の防災啓発映像に使える程度の写実性**です。

見せ物としての派手さではなく、

「水がどう来て、どこに溜まり、何が起きるか」が正確に伝わることを最優先にしてください。

「平面のテクスチャが街の上を滑っていく」作品ではなく、

以下を一体化した浸水環境を作ってください。

* 海底から海岸、護岸、道路、宅地へ連続する地形

* 一般的な沿岸住宅街の街区（無地・オリジナル）

* 海から到達する津波（段波の形成、越流、遡上、引き波、第2波以降）

* 建物・擁壁・street に沿った流れの偏り

* 濁流（土砂・漂流物・泡）としての水の見え

* 浸水したまま残る湛水、濡れ跡、泥の堆積

* リセットして何度でも同じ条件で再現できること

* 上空・街路・建物屋上・水面すれすれを連続移動できる視点

**人物・生物は今回は一切登場させないでください。**

避難行動の描写、被災者の描写、人的被害の示唆はしないでください。

## 0. 最優先の実行体制：サブエージェント禁止

本制作では、サブエージェントを一切使用しないでください。

以下を禁止します。

* サブエージェント

* 補助エージェント

* 子エージェント

* 並列エージェント

* エージェントチーム

* 別エージェントへの委譲

* 別エージェントへの引き継ぎ

* `spawn_agent` または同等機能の使用

* 同一成果物を複数エージェントで分担編集すること

* 評価、実装、検証、梱包のいずれかを別エージェントへ任せること

この会話を担当する単一のAIが、最初から最後まで一貫して制作してください。

長時間作業になった場合も、サブエージェントを追加してはいけません。

現在の担当AIがチェックポイントを作成し、必要に応じて作業を再開してください。

通常のツール、ブラウザ、レンダリング処理、検証処理、保存機能、

非エージェント型の並列処理は使用して構いません。

ただし、設計判断や編集作業を別のAI主体へ委譲してはいけません。

この実行体制は、プロンプト内の他の指示より優先してください。

## 1. 最重要：これは防災啓発用途である（倫理・表現の制約）

本作は災害を扱います。以下は他のすべての要求より優先されます。

### 1.1 実在地の再現を禁止

* 実在の市町村名、地区名、河川名、港湾名、施設名、企業名、商標を使用しない

* 実在のハザードマップ、被害想定、浸水想定区域図を再現・模写しない

* 実在の災害の映像・写真を再現しない

* 建物は無地でオリジナルの意匠にする（実在建築物を特定できる形にしない）

* 地形は架空の沿岸地形とする

### 1.2 予測・保証を装う表現を禁止

* 「この地域はこうなります」等、特定地点の被害を示唆する表現をしない

* 表示される波高・到達時間・浸水深は、**利用者が設定した仮想の入力値に対する

  数値計算結果**であり、いかなる実在地点の予測でもないことを明示する

* 避難の可否、安全な場所、避難経路を示唆・推奨しない

* 「安全」「大丈夫」「ここまでは来ない」といった判断を与えない

### 1.3 必ず表示する免責（About と、動画書き出し時の焼き込み）

* 本作品は架空の地形を対象とした**視覚シミュレーション**である

* 実在の地域の被害予測・浸水想定ではない

* 実際の津波は、地形、地盤変動、潮位、構造物、漂流物などの影響で

  本作の計算と大きく異なりうる

* 避難の判断は、気象庁の津波警報・注意報、自治体の避難情報、

  現地の指示に必ず従うこと

* 本作の数値を防災計画・避難計画の根拠に用いないこと

### 1.4 演出上の節度

* 破壊、流失、人的被害を煽情的に描かない

* 効果音を実装する場合、恐怖を煽る演出にしない（無音でもよい）

* 色使いは、防災資料として読みやすい配色を優先する

## 2. 水理計算：本作の中心

**「水面の高さテクスチャをアニメーションさせる」実装を禁止します。**

水は、**2次元浅水流方程式（非線形長波・水深平均）を実際に解いて**ください。

```

∂h/∂t + ∂(hu)/∂x + ∂(hv)/∂y = 0

∂(hu)/∂t + ∂(hu²+gh²/2)/∂x + ∂(huv)/∂y = -gh ∂z_b/∂x - τ_x/ρ

∂(hv)/∂t + ∂(huv)/∂x + ∂(hv²+gh²/2)/∂y = -gh ∂z_b/∂y - τ_y/ρ

```

必須要件：

* **well-balanced**（静水は静水のまま。地形の傾斜で勝手に流れ出さない）

* **wet/dry フロントを安全に扱う**（h→0 で速度が発散しない、NaN を出さない）

* **保存形**で解き、質量保存を数値で検証できること

* **CFL 条件**を守る（可変Δt または十分小さい固定Δt ＋ サブステップ）

* 底面摩擦は Manning 則。粗度係数を土地利用ごとに変える

  （海面／砂浜／舗装道路／宅地／植生／建物周り）

* 構造物（建物・擁壁・防潮堤）の扱いを明示する

  * 地形の隆起として扱う（推奨・簡便）／反射境界として扱う のどちらでもよい

  * ただし採用した方式と、その限界を README に書くこと

* 開境界（沖側）で波を反射させない（放射条件または吸収層）

スキームは問いません（HLL/HLLC、Kurganov–Petrova、Lax–Friedrichs 系、

セミラグランジュ＋圧力投影 など）。ただし上記要件を満たすこと。

GPU（フラグメントシェーダ or WebGL2 の複数レンダーターゲット）での実装を推奨します。

### 2.1 解像度と範囲

* 計算格子は**街路の幅を解像できる**こと（目安 1〜2 m/セル）

* 計算範囲は目安 1〜2 km 四方

* 格子解像度・範囲は品質設定で変えられるようにし、

  **解像度を変えても結果の傾向が大きく変わらない**ことを確認する（収束性の確認）

### 2.2 入射波（津波の与え方）

沖側境界から、次のいずれかで与えてください。

* 水位時系列を与える（推奨：制御しやすく、検証しやすい）

* 初期水位分布（隆起・沈降）を与えて自然に伝播させる

必ず実装する挙動：

* **引き波先行**（海面がいったん下がってから押し波が来る）を切り替えられる

* **段波（bore）の形成**（岸に近づくにつれ波面が切り立つ）

* **第2波・第3波**（1波目より大きい場合があることを表現できる）

* 遡上（陸上を駆け上がる）と、その後の**引き波**

* 護岸・防潮堤の**越流**と、越流後の落下・跳水

* 岸壁・建物からの**反射波**

## 3. 地形と街のデザイン

デフォルトの舞台は、実在地を直接再現しない架空の温帯沿岸としてください。

構成：

* 沖 → 浅瀬 → 砂浜または護岸 → 海岸道路 → 住宅街 → 背後の緩やかな高台

* 標高は 0〜20 m 程度。**浸水深 0.1 m 単位の差が見える精度**を持たせる

* 海岸線は直線にしない

* 街区は格子状でよいが、完全な均一格子にしない（幅の違う道路、袋小路、空地）

* 建物は 2 階建て住宅を中心に、低層店舗、倉庫、集合住宅を混ぜる

* 電柱、ガードレール、擁壁、側溝、駐車車両など、水の流れを変える要素を入れる

* 河川または水路を 1 本入れると、**河川遡上**が表現できて価値が高い

* 防潮堤・護岸の高さをパラメータにする（越流の有無を比較できる）

地形と街と水は、同じ標高データ・同じ座標系を共有してください。

建物の基礎高さ、道路面、地盤面が矛盾しないようにしてください。

以下を発生させないでください。

* 建物が地面に埋まっている／浮いている

* 道路と宅地の標高が不連続に飛ぶ

* 水面と地面の交差部に黒い線、隙間、Z-fighting、点滅

* 計算格子の境界が見える

* 街区の端で地形が唐突に切れる

## 4. 水の見え方（濁流としての写実性）

**津波は透明な青い水ではありません。** ここを間違えると一気に嘘になります。

* 基本は**土砂を含んだ濁流**（茶〜灰褐色）。透明度は低い

* 濁度は流速・水深・巻き上げ量から決まる（一様な色を塗らない）

* 浅い水（数 cm〜数十 cm）では下の路面・地面が透けて見える

* 深い水では底が見えず、濁った色に収束する

* 水面の反射は**弱い**（濁った水はほとんど鏡にならない）。

  ただし静穏になった湛水面は、時間とともに澄み、反射が増える

* 白泡は、波面（bore front）、越流部、建物・障害物の後流、跳水部に出る

* 泡は履歴を持つ（発生・移流・拡散・減衰）。全面に広げない

* 流速が見えること（表面のスジ、渦、変形する泡パターン）

* 漂流物（木材、車両、コンテナ、瓦礫）を少量入れる。

  **水の流速場に従って流されること**。品質が水に劣る場合は数を絞る

以下を避けてください。

* 青く澄んだ「海の水」

* 一様な茶色の板

* 水面が鏡になっている

* 泡が街全体を覆う

* 泡が水と無関係に漂う

* 流速があるのに水面が静止して見える

* 浅い水が真っ黒／真っ白になる

* 漂流物が水と無関係に動く、または水面に貼り付いて回転しない

---

## 5. 浸水後：湛水・濡れ跡・堆積

依頼の中心のひとつです。**1 回の津波が過ぎたあと、街は水浸しのまま**にしてください。

* 低地には水が**残る**（排水は非常に遅い、または排水しない設定をデフォルトにする）

* 高い場所からは水が引く

* 引いたあとに以下が残る：

  * 建物・壁の**水位痕（watermark）**：最高浸水位の高さに帯として残る

  * 濡れた路面・地面（時間をかけて乾く）

  * 泥・砂の**堆積**（流速が落ちた場所に厚く）

  * 漂流物の滞留（引っかかった場所に残る）

* 最高浸水位、最大流速、到達時刻は**セルごとに記録**し、後から表示できるようにする

以下を避けてください。

* 波が過ぎたら水が一瞬で消える

* 湛水が地形と無関係な形で残る（高台に水たまりができる等）

* 濡れ跡が全面に一様に付く

* 水位痕の高さが実際の最高水位と一致しない

* 泥が永久に増え続ける／一切残らない

## 6. 計測表示（防災資料として使うための機能）

トグルで ON/OFF できる情報表示を実装してください。

* **浸水深の段階配色**（凡例つき。防災資料で一般的な段階に近い区分：

  例 0.1 / 0.3 / 0.5 / 1.0 / 2.0 / 3.0 / 5.0 m 以上）

* **流速の段階配色**（凡例つき）

* **到達時刻マップ**（各地点に水が達した時刻）

* **最高浸水位マップ**

* 任意地点のプローブ（クリックでその地点の水深・流速・到達時刻の時系列を表示）

* 断面図（指定した測線に沿った地形・水位のグラフ）

* 経過時間の表示

* スケールバー（距離）と方位

配色は色覚多様性に配慮したものにしてください（赤緑のみで区別しない）。

数値には必ず単位を付けてください。

**これらの表示は「架空の入力値に対する計算結果」であることを画面上でも示してください。**

## 7. カメラと操作（指定どおりに実装すること）

マウス操作は以下を**必ず**この割り当てで実装してください。

| 操作 | 動作 |

|---|---|

| **左ドラッグ** | 視点の向きを変える（上下＝ピッチ、左右＝ヨー） |

| **右ドラッグ** | 視点を上下左右に平行移動する |

| **右ドラッグ + Shift** | 視点を前後に移動する |

補足要件：

* 右クリックのコンテキストメニューは抑止する

* 感度を設定できる、または妥当な既定値にする

* ピッチは真上・真下付近でジンバルロックしないようクランプする

* カメラのロールは常に 0（水平を保つ）

* 移動速度は視点高度に応じて自動調整してよい（低いほど遅く）

* ホイールの割り当ては任意（前後移動または画角）。指定の 3 操作を上書きしないこと

* タッチ操作でも同等のことができるようにする

  （1本指＝向き、2本指ドラッグ＝平行移動、2本指ピンチ＝前後）

* 地面・建物への潜り込みを防ぐ、または明示的に許可する

* リセット操作（視点を初期位置へ）

さらに、検証と映像制作のためのプリセット視点を用意してください。

1. **Offshore** 沖合から街を見る

2. **Coast Line** 海岸線を横から見る（越流が見える）

3. **Street Level** 街路の目線高さ（水が来る方向を向く）

4. **Rooftop** 屋上高さから街区を見下ろす

5. **Aerial Wide** 上空から街全体

6. **Aerial Top** 真上（浸水範囲が読める）

7. **Waterline** 水面すれすれ（段波の前面）

8. **Behind Building** 建物の背後（回り込みと後流）

9. **River** 河川・水路の遡上

10. **After** 浸水後の湛水と痕跡

## 8. 進行制御とリセット

* 再生 / 一時停止 / コマ送り

* 時間速度（0.1× 〜 4×）

* 経過時間の表示とシーク（可能なら）

* **リセットボタン**：押すと初期状態に戻り、同じ条件で津波を再現できる

  * 水位、流速、泡、濁度、湛水、濡れ跡、堆積、水位痕、漂流物、

    最高浸水位、到達時刻マップ、**すべてを初期化する**

  * リセット後の状態が、初回起動直後と**完全に一致する**ことを検証する

* 「水だけリセット（痕跡は残す）」を別ボタンで用意してもよい

* 条件を変えて再実行できる（波高、周期、引き波先行、防潮堤高さ、粗度など）

* **決定論的であること**：同じ設定・同じ時刻なら常に同じ結果になる

---

## 9. 空・光・天候

* 標準は**昼間・薄曇り〜晴れ**（防災映像として視認性を優先）

* 影が濃すぎて浸水域が読めなくならないようにする

* 時刻プリセット（朝／昼／夕）は任意

* 夜間・豪雨は必須ではない。まず昼間の視認性の高い状態を完成させる

* 大気遠近を入れ、遠景の街と海が自然に霞む

* 白飛び・黒つぶれで浸水状況が読めなくならないこと

## 11. パフォーマンス

最高品質だけでなく、実際に操作可能な速度を維持してください。

デスクトップ向けには、必要に応じて以下を使用してください。

* GPU 上での浅水流ソルバ（ping-pong テクスチャ、RGBA32F/16F）

* 可変サブステップ（CFL に応じて 1 フレームあたり複数回解く）

* 建物・道路のインスタンシング

* 適応的LOD

* 高解像度の泡・濡れ・堆積履歴

モバイル向けには、自動的に以下を調整してください。

* 計算格子解像度（ただし街路が潰れない下限を守る）

* サブステップ数

* 泡・堆積履歴の解像度

* 建物のポリゴン数・描画距離

* 漂流物の数

* 描画解像度

* ポストエフェクト

ただし、モバイルでも以下は維持してください。

* 浅水流の実解法（見た目だけの近似に置き換えない）

* 質量保存と wet/dry の安定性

* 越流・遡上・引き波

* 湛水と水位痕

* 浸水深の段階配色と凡例

* 指定のマウス／タッチ操作

* リセットの完全性

* 外部通信なしでの起動

代表的な実行環境でFPSを実測してください。

実GPUで測定できない場合は、その制約を明記し、

測定できていない性能を推測で保証しないでください。

## 12. 配布条件

最終成果物は、通常のブラウザからダブルクリックで起動できるようにしてください。

必須条件：

* ダブルクリック用の単一HTML

* `file://`で起動可能

* ローカルサーバー不要

## 13. 数値検証（本作で最も重要な検証）

以下を**自動検証スクリプトから数値で**出力してください。

### 13.1 ソルバの正しさ

* **静水テスト（lake at rest）**：

  傾斜地形＋静水で 1000 ステップ回し、最大流速が閾値以下であること

  （well-balanced でないとここで必ず流れ出す）

* **質量保存**：

  流入量 − 流出量 − 領域内保有量 の誤差率（目標 1 % 未満）

* **CFL 数**：全ステップの最大値が 1 未満であること

* **NaN / Inf**：水深・流速・保存量のすべてでゼロ

* **収束性**：格子解像度を 2 倍にしたとき、

  最高浸水位・到達時刻の分布が大きく変わらないこと（差分を報告）

* **時間刻み依存性**：Δt を半分にしても結果が大きく変わらないこと

### 13.2 標準ベンチマークとの比較（強く推奨）

少なくとも 1 つは実装し、解析解または既知の結果と比較して誤差を報告してください。

* **1次元ダムブレイク**（Stoker の解析解）：水位・波面速度の比較

* **傾斜面上の遡上**（Carrier–Greenspan / Synolakis の孤立波遡上）：最大遡上高の比較

* **円形ダムブレイク**：対称性が保たれるか（数値異方性の確認）

これは「浅水式を使ったから自然」という自己申告を排除するための項目です。

### 13.3 演出としての整合

* 建物への浸水深と、建物周りの最大流速の分布

* 到達時刻マップの妥当性（沖から順に到達しているか、逆流していないか）

* リセット前後の状態一致（全バッファのハッシュ比較）

* 決定論性（同一設定で 2 回実行し、全バッファが一致するか）

### 13.4 画づくりの客観指標

* 画面の平均輝度・白飛び率・黒つぶれ率

* 泡が画面を覆う割合（覆いすぎ検出）

* 水面色の彩度分布（青すぎ＝海水に見えていないかの検出）

## 18. 品質判断の原則

名称や実装方式だけで品質を判断しないでください。

以下のような判断は禁止します。

* 浅水式を使ったから物理的に正しい

* HLL を使ったから安定

* GPU で解いているから高速

* 濁った色にしたから津波に見える

* 泡があるから迫力がある

* 段階配色を付けたから防災資料として使える

* シェーダーがコンパイルできたから完成

* 静止画がきれいだから動画も合格

* 機能が実装されているから視覚的にも十分

本作では、次の連続性を最優先してください。

**沖の水位変動 → 浅水化と段波形成 → 越流 → 街路への流入 →

建物による分流・回り込み → 最大浸水 → 引き波 → 湛水 → 痕跡（水位痕・堆積）**

どこか一つだけ高品質でも、全体が連動していなければ完成扱いにしないでください。

試作結果が悪ければ、採用予定だった方式でも戻してください。

不採用案、一時画像、古い版、失敗データを最終納品物へ混ぜないでください。
